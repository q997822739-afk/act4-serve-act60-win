写库的规矩—— 点开看：什么时候要停服、改完什么时候生效

发放物品可以不停服：服务端在跑时，发放走邮箱 —— 后端往邮件表追加一封 不过期的系统邮件（服务端自己背包满时也这么寄：礼包拆出的、商城买的都寄邮箱）。这张表只被 整行插入、单行改删，服务端不会拿内存整块覆盖它，所以运行中发是安全的。 角色正在游戏中时，服务端会在线把邮件推给他（不用小退，邮箱里直接能领、还会弹提醒）； 角色停在选择界面则进游戏后领取。投递出去的邮件在「背包 / 穿戴」页底部的「邮箱」里查看/删除。

其余写操作（含改基础职业 / 转职）默认仍只在服务端停止时可用：等级 / 经验 / SP / 金币 / 点券 / 决斗胜点 / 疲劳 / 改基础职业 / 转职、 背包与穿戴编辑、清背包、技能、任务、GM 名单、复制 / 删除角色 —— 这些改的是服务端内存里 拿着、存档时整块写回的数据，直写会被覆盖。

不停服的第二种做法：小退到选择界面（2026-10-09 加，2026-10-10 起自动识别）。在游戏里小退到 【角色选择界面】（不要进入任何角色）后，服务端已经把背包 / 技能 / 数值这些整块数据存好并释放了。 现在服务端会自己记录"角色在不在游戏里"（库里一张在线状态表），所以本工具 按角色自动判断：你要改的角色不在游戏里就放行，直接点保存即可 —— 不用再点任何开关。 角色一旦进游戏，写同一个角色又会被自动拒掉。

（只有一种例外：如果你换的是旧版服务端 jar（没有在线状态表）， 工具无法自动判断 —— 那时顶栏会出现「已小退」手动开关，按老办法在游戏里小退后点开它即可。）

顺序（停服那条路）是「启动器【停止服务端】 → 网页 GM 里改 → 启动器【启动服务端】 → 客户端重新选角」。这些写操作每次都会先自动备份整库到 data\webgm-backups\（服务端在跑时走 SQLite 自己的一致快照，不会备份到半截文件）。

时装例外：时装在线发放是直接往装扮栏插一行（同样是追加，服务端 对这张表也只有整行插入 / 单行挪槽 / 单行删）。在线时别同时在游戏里买 / 合成时装 —— 挑的空槽可能和游戏里那件撞上。

改完什么时候生效：
① 背包 / 金库 / 穿戴 / 时装 / 技能 / 任务 —— 这些在每次选择角色时由服务端重读，重新选角即生效；
② 等级 / 经验 / SP / 金币 / 点券 / 决斗胜点 / 疲劳 / 基础职业 / 转职 —— 角色表字段，重新选角时读；
③ GM 名单 —— 服务端启动时装载（账号编号清单），改完要重启服务端；
④ 改基础职业 —— 写职业编号的同时把转职清零、按新职业的初始技能重建技能表、按等级重算 SP（等同"建一个该职业的新角色"），重新选角即生效；
⑤ 转职 —— 写转职值的同时已经按新分支重建技能表、按等级重算 SP（走服务端转职命令那套逻辑），重新选角即生效，不需要再进游戏敲 #clear all skill。（如果 PVF 没读到、重建失败，会退回"只写字节"并在回执里提示。）
