# ACT5 插件说明规范 v1（插件元数据 + 启动器展示）

> **它管什么**：插件 DLL 的"人话说明"怎么写、启动器【DLL 扩展】页怎么读怎么显示、
> 插件加载优先级（ini 顺序）怎么排。
> **它不管什么**：插件怎么加载（那是 `dll_ext.ini` + 扩展宿主的事，见
> 《[DLL开发指南](DLL开发指南.md)》与 `ext_host.cpp`）、插件怎么实现功能
> （各插件自己的事）。
> 本规范**纯展示层** —— 宿主不认识本文件，`dll_ext.ini` 里永远只有 `N=文件名.dll`，
> 删掉本规范相关的一切，插件照常工作。

---

## 一、元数据四级回退链（启动器解析顺序）

启动器【DLL 扩展】页为每个插件显示"一句话小字"，【详细】按钮展示完整说明。
说明内容按以下顺序取**第一个命中的来源**（要么整体采用要么整体跳过，**不跨级合并**）：

| 级 | 来源 | 谁提供 | 何时用 |
|---|---|---|---|
| 1 | **随件说明文件** `<DLL名>.plugin.json` | 插件作者 | 信息最全（含注意事项/主页），**推荐的正规姿势** |
| 2 | **启动器内置目录**（md5 → 文案表） | 启动器维护者 | 只收实测验证过的插件，开箱即得 |
| 3 | **文件属性**（PE 版本资源 `FileDescription` 等） | 插件作者 | 编译时顺手写进 DLL 的标准 Windows 元数据 |
| 4 | **默认文案** | — | "未提供说明（第三方插件，启用前请自行确认来源）。" |

规则：

- 每一级的读取**绝不 LoadLibrary 插件** —— 启动器只读文件（JSON 解析 / 版本资源 API / md5），
  **第三方代码永远不在启动器进程里执行**。这是硬规矩，不是优化。
- 级 2（内置目录）按 **md5 命中**才采用：文件与我们描述时的字节一致才敢替它说话。
- 缺失/损坏的字段不阻塞：坏 JSON → 当没有；`schema` 高于本版 → 当没有（向前兼容）。
- 中文一律 UTF-8（无 BOM）。**UTF-16 的 `.plugin.json` 不支持**（与 `dll_ext.ini` 同规）。

## 二、随件说明文件规范（插件作者按此写）

### 2.1 文件规则

- **命名**：与 DLL 同名，后缀固定 `.plugin.json`。
  例：`MyPlugin.dll` ↔ `MyPlugin.plugin.json`（大小写不敏感匹配）。
- **位置**：和 DLL 放在一起。启动器【导入 DLL】时若发现同目录有同名 `.plugin.json`
  会一并收进扩展目录；也可以把它打进插件发布 zip。
- **编码**：UTF-8（无 BOM）。
- **不会被复制进客户端目录**：说明文件只给启动器看，宿主不读它，客户端目录保持干净。

### 2.2 字段表（schema 1；全部可选，未知字段必须忽略）

| 字段 | 类型 | 说明 |
|---|---|---|
| `schema` | number | 规范版本，写 `1`（可省略，缺省 = 1；启动器遇到更高版本按"没说明"处理） |
| `name` | string | 展示名（如 "DFO 手柄震动"），【详细】窗标题；省略 = 显示文件名 |
| `version` | string | 插件版本（如 "1.0.0"），自由文本 |
| `author` | string | 作者/团队 |
| `summary` | string | **一句话说明**（列表页小字 + 详情首行），建议 ≤ 40 字 |
| `notes` | string[] 或 string | 注意事项，每条一行（【详细】窗逐条列出；单个字符串 = 一条） |
| `homepage` | string | 主页/发布页 URL（【详细】窗可点开） |

### 2.3 完整例子

```json
{
  "schema": 1,
  "name": "我的插件",
  "version": "1.0.0",
  "author": "你的名字",
  "summary": "一句话说明：这个插件干什么用的",
  "notes": [
    "注意事项一：比如与某个功能互斥、或者要重启客户端生效",
    "注意事项二：比如只在某个客户端版本上验证过"
  ],
  "homepage": ""
}
```

放到客户端目录里随插件一起交付（或打进发布 zip），启动器导入时会一并收下。

## 三、文件属性约定（第 3 级来源）

没有随件说明时，启动器读 DLL 的标准版本资源（`VS_VERSIONINFO`）：

| 版本资源字段 | 用途 |
|---|---|
| `FileDescription` | 一句话说明（列表小字） |
| `Comments` | 注意事项（按行拆成多条） |
| `ProductVersion`（缺省回退 `FileVersion`） | 版本 |
| `CompanyName` | 作者 |

写法：写一个 `.rc`（`StringFileInfo` 的 `080404b0` 或 `040904b0` 块）编进 DLL 即可；
LLVM-MinGW 用 `windres`，MSVC 直接把 `.rc` 加进工程。

注意：**`FileDescription` 为空 = 本级跳过**，不是报错。

## 四、内置目录维护（启动器侧，第 2 级来源）

- 位置：`启动器源码\Services\DllExtService.cs` 的 `BuiltinCatalog`（md5(小写) → 元数据）。
- **只收实测验证过的插件**：描述必须与该 md5 的文件实际行为一致 —— 它是我们替作者说的话。
- 文件变了（作者发新版）md5 变 → 目录条目自动失配 → 回退到第 3/4 级；维护者更新表即可。
- 新增/修改条目的提交必须附该 md5 的来源（哪个构建、谁验证的）。

## 五、加载优先级 = `dll_ext.ini` 条目顺序（拖拽排序）

- 宿主按 `dll_ext.ini` `[plugins]` 节的**行序**逐个加载插件，
  行序即加载优先级（见《DLL开发指南》§6.2）。
- 启动器【DLL 扩展】页每行的 **⋮ 手柄按住上下拖动 = 调整顺序**；松手即存进
  `extensions.json` 的排序记录（文件名序列）。
- **挂载时 ini 的写入顺序** = 玩家手工条目（指向扩展目录之外 dll 的行，位置内容都不动，
  排最前）→ 启动器管理的条目按排序记录排其后。手工条目指向的 dll 若进了扩展目录，
  就升级为"启动器管理的条目"，跟随拖拽顺序。
- 撤下/删除会同步维护排序记录；`extensions.json` 删掉 = 清空勾选**和**排序
  （回退按名称序）。

## 六、启动器侧实现备忘

- `Services\DllExtService.cs`：
  - 元数据：四级回退链解析、随件 JSON 宽容解析、内置目录、PE 版本资源读取。
  - 库与清单：扩展库目录（`runtime\DLL扩展\`）、`extensions.json`（启用项 + 排序）、
    备份子目录（`备份\`，撤下时还原被同名顶掉的客户端文件）。
  - 动作：`Import`（导入，随件说明一并收下）、`Deploy`（按序写 ini + 拷文件 + 回读校验）、
    `Undeploy`（撤下 + 还原）、`Delete`（连带删说明与排序项）。
- `Views\DllExtView.xaml(.cs)`：页面。**`A5.dll` 那一行是强制开启、不可关闭**的
  （它是客户端补丁而不是插件，不进 ini、不参与挂载；缺失时页面给醒目提示）。
  插件行 = 名称 + 小字说明 + 开关 + ⋮ 拖拽手柄 +【详细】按钮。
- `Views\DllExtDetailWindow.xaml(.cs)`：完整说明弹窗（可选字段整行隐藏，主页可点开）。
- 绑定模型类（如 `DllExtItem`）的成员一律写**属性**不能写字段
  （WPF `{Binding}` 对字段静默失败 —— 这边踩过这个坑）。

## 七、版本升级

- 本文件为 **v1**；改字段语义必须 `schema` +1，并在启动器侧保留旧版解析或显式降级
  （当前实现：`schema` > 已知版本 = 整份跳过，走回退链，绝不猜）。
- 启动器遇到 `schema: 2` 的说明文件会显示默认文案，不会崩 —— 这是有意的。
